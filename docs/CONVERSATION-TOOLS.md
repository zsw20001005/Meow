# Windows 对话工具与动作

0.2.0 在现有聊天入口接入应用内笔记、提醒、信箱和页面操作。数据仍保存在原有本机存档目录；不会访问任意系统文件或运行命令。

## 可以直接尝试

- `记下：周末买牛奶`：无需模型即可存入小本本的“笔记”页。
- `打开记事本`、`打开信箱`：无需模型即可打开页面。
- `把购物清单里的牛奶改成酸奶`：先查找原文，再修改唯一匹配的笔记；支持追加、归档，归档后可在笔记页恢复。
- `明天上午九点提醒我开会`：保存本机提醒。只说“提醒我开会”时需补充具体时间。
- `帮我写一封信，告诉对方今天玩得很开心`：拟写并保存草稿，在回复中展示正文及绑定收件设备。核对后再说 `寄出这封信`。需先在信箱开启通信并绑定设备；写草稿本身不发送。
- `看看未读来信`、`刚才的信送达了吗`：读取实际信件或查询队列状态。
- `噜噜，先挥挥手，然后转个圈，最后点点头`：依次播放三个动作。
- `不要睡觉，挥挥手`、`别睡了，起来挥手`：分别处理否定、起床和后续动作。
- `散步`、`停止散步`、`保持当前表情`、`恢复自由活动`：使用现有持续状态与动作控制。

自然语言改写、拟信及复杂操作使用设置中选定的云端或本地对话模型。精简安装版不附带本地模型。此版本只修改 Windows 实现，未修改 macOS Swift 端。

## 实现约定

在已有行为 JSON 中加入 `tools`，沿用现有 OpenAI 兼容与 Anthropic 文本接口，不依赖特定供应商原生 function calling。工具限定在 `ConversationTools` 白名单内，单批最多 4 项；行为队列最多 6 个不同动作。模型必须能遵循结构化输出要求。

程序先校验工具与参数再执行，格式错误最多修复一次。笔记的查询后修改最多追加两轮模型请求，因此这类请求可能比普通聊天使用更多调用。操作结果来自本机执行器；模型自己的“已保存”不作为成功依据。取消回复不会撤销已保存的操作。

寄信仅发送此前已展示、绑定设备未改变的草稿，以草稿 ID 去重。回执区分待寄、送达和取消，网络失败保留待寄队列。笔记、信件内容作为数据处理，不授予额外工具权限。

## 验证

- `Meow.exe --selftest`：现有协议解析与存档检查。
- `Meow.exe --toolcheck`：工具授权、参数、持久化、回滚、提醒、寄信去重与动作解析。
- `Meow.exe --chattoolcheck`：真实聊天处理器连接隔离的本机模拟模型，验证保存、查询后修改、补充提醒时间、格式修复和笔记页渲染。
- `Meow.exe --conversationcheck`：实际动画队列与起床后继续动作。

这些检查不读取真实账号、不调用付费模型、不寄送真实信件。实际服务商的自然语言理解效果及真实信箱传输需在用户自己的配置下体验。

## 0.2.1 多轮上下文修复

普通聊天原本已发送最近 30 条消息。本次修复的是工具校验丢失上文的问题：说完“记下：明天12点午睡”，再说“这个加到备忘录”，执行器会沿用上一条用户内容；澄清错别字后只回复“午睡”，也能继续原提醒并保留时间。

未完成的提醒澄清保存在本机，10 分钟内可继续（包括重启后）。保存成功、取消、转移话题、清空聊天或相关记忆时清除。只用于续接提醒，不把简短确认当作寄信授权。输出中的 JSON 控制字段泄漏会先尝试一次格式修复，持续失败则显示错误而不执行。

新增模拟聊天回归检查：相邻问答的实际请求历史、笔记转提醒、短词纠错、澄清跨重启、取消/过期上下文以及控制字段泄漏。
